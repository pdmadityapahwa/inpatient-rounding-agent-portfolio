The development journey

One stage informs the next.

A connected record of what we explored, where AI helped, and which product decisions I owned. The timeline also shows where evidence is still missing.

01 · DISCOVERY

Start with the clinician’s workday

Hospitalists and physicians prepare inpatient progress notes before rounds. The feature enters at the existing copy-forward moment; the clinician reviews, edits, and signs the result. Initial planning assumptions were about 200 notes per site per day and 15 minutes per note—roughly 50 staff-hours, if validated.

Codex organized the discovery inputs and calculated the implied time. It did not conduct clinician interviews or validate the baseline.

I framed the initial user, workflow boundary, human sign-off, and assumptions; I marked volume and time as unvalidated.

02 · IDEATION & EXPERIENCE

Make the workflow tangible

The concept became Copy Forward with AI: a source-linked editable SOAP draft, phrase-level highlights for changed content, and a failure state showing the previous note unchanged. A reviewer can inspect the simulated workflow without confusing it for a live EHR feature.

Codex generated and iterated a local HTML prototype with hard-coded simulated results. No model or EHR was connected.

I chose a high-fidelity interaction to explore, requested selective highlights, reviewed the iterations, and accepted it as a workflow artifact.

03 · DATA & EVALUATION SETUP

Design the cases before judging the agent

One fictional heart-failure case combines a chart, prior note, handoff, and transcript. Its traps distinguish active from discontinued orders, one-time from daily medication, timestamped measurements from recollection, pending tests from results, and discussion from an entered order.

Codex helped author and inspect the synthetic packet and draft provisional candidate-fact labels. No LLM judge was used.

I set the scenario intent and fact-level evaluation unit. Clinical SMEs—not the PM or model—must validate clinical ground truth.

04 · REQUIREMENTS & DECISIONS

Turn risk tolerance into measurable gates

Project targets: ≥95% retrieval recall, ≥95% precision, and 0% unsupported statements in evaluated drafts. The workflow target is a draft within 10 seconds, with up to three retries and an unchanged prior-note fallback after failure. These are thresholds to test—not demonstrated performance.

Codex helped structure requirements, explain evaluation metrics, and compare retry and cost trade-offs.

I selected the targets, kept retrieval and documentation evaluation separate, chose retrying only the failed agent, and declined paid inference for this portfolio.

05 · TWO-AGENT IMPLEMENTATION

Separate evidence selection from note writing

The design uses two model responsibilities with code-owned orchestration, source-reference checks, bounded retries, a shared deadline, and JSONL usage logs. The app contains an initial Python implementation. A launch reached the API but stopped before generation because the account had no credits.

Codex drafted the two-agent Python scaffold and documented the API/SDK boundary and known limitations.

I kept the human approval boundary, requested per-agent visibility, chose to retry only the failing agent, and made cost a measured input rather than an invented requirement.

06 · EVALUATION & RELEASE DECISION

Keep claims aligned with evidence

I chose not to purchase API credits. There are no successful model outputs, repeated runs, confusion matrices, clinician-approved labels, cost-per-draft measurements, or ship-gate verdict. The portfolio shows the evaluation plan and reports its limits plainly.

No model-based evaluation occurred. Codex helped record the failed billing attempt and mark targets as unevaluated.

I set the no-paid-inference scope and prevented planned targets from being presented as results or clinical claims.

The two-agent workflow

Two agents prepare the draft. The clinician signs.

Each agent has one clear job, with a clinician reviewing the result before it is signed.

1

Start the draft

From the Notes screen, click Copy Forward with AI.

2
RETRIEVAL AGENT

Find relevant updates

Selects current details from the chart, handoff, transcript, and prior note.

3
DOCUMENTATION AGENT

Draft the SOAP note

Writes from selected evidence, highlights changed phrases, and links each detail to its source.

4

Edit and sign

The clinician makes any edits and signs the note.

If the system can’t prepare a draft

After three retries, it shows the previous note unchanged and warns that today’s context was not added. The clinician still reviews and signs.
